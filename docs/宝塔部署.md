# 宝塔面板部署指南

面向「橙曦澎湃 / Prax」门户网站。整个过程约 10 分钟，全程在宝塔面板里点鼠标 + 粘几行命令。

---

## 零、先看这一条（最容易踩的坑）

**Node.js 版本必须 ≥ 22.13.0，推荐 24 LTS。**

本项目用 Node **内置**的 `node:sqlite`，好处是零原生编译、不用装数据库；
代价是版本有硬要求：

| Node 版本 | `node:sqlite` 能否直接 require |
| --- | --- |
| 22.5.0 ~ 22.12.x | ✗ 必须加 `--experimental-sqlite` 标志 |
| **22.13.0 及以后** | ✓ 可以直接用 |
| 23.4.0 及以后 / 24.x | ✓ 可以直接用 |
| 25.7.0 及以后 | ✓ 转为 release candidate |

> 如果你在宝塔上装了 22.5~22.12 之间的版本并直接启动，会看到
> `ERR_UNKNOWN_BUILTIN_MODULE: No such built-in module: node:sqlite`。
> 本项目已内置版本自检，会提前拦住并给出中文提示，而不是甩一句看不懂的报错。

---

## 一、安装运行环境

### 1. 装 Node.js（用宝塔的版本管理器）

宝塔面板 → 左侧 **网站** → 顶部 **Node 项目** → 首次进入会提示安装「Node.js 版本管理器」，点安装。

装好后在版本列表里**安装 v24 LTS**（或任意 ≥ 22.13 的版本），然后**把它设为默认版本**。

> 若面板没有 Node 版本管理器（老版本宝塔），也可以在软件商店搜
> 「PM2管理器」安装，它自带 Node 版本选择。

### 2. 装 PM2（进程守护）

宝塔 → 软件商店 → 搜 **PM2管理器** → 安装。
（若上面用 Node 项目管理器，它内部也带 PM2，二选一即可。）

---

## 二、上传项目

### 方式 A：面板上传（推荐新手）

1. 把项目文件夹压缩成 zip（**压缩前先删掉 `node_modules` 和 `data`**，这两个会在服务器上重新生成）
2. 宝塔 → **文件** → 进入 `/www/wwwroot/` → 新建目录 `prax` → 进入
3. 上传 zip → 右键 **解压**

最终路径应为：`/www/wwwroot/prax/`（里面能看到 `server/`、`public/`、`package.json`）

### 方式 B：Git 拉取（需要仓库）

宝塔 → 文件 → 终端，或 SSH 执行：

```bash
cd /www/wwwroot
git clone <你的仓库地址> prax
cd prax
```

---

## 三、安装依赖

宝塔 → **文件** → 进入 `/www/wwwroot/prax` → 点顶部 **终端**（或用 SSH），执行：

```bash
cd /www/wwwroot/prax
npm install --omit=dev --no-audit --no-fund
```

> `--omit=dev` 表示不装开发依赖，装得更快更小。
> 如果 `npm install` 报权限错，先执行 `chown -R www:www /www/wwwroot/prax`。

---

## 四、启动服务

### 方式 A：用「Node 项目」图形化启动（最省事）

宝塔 → **网站** → **Node 项目** → **添加 Node 项目**

| 字段 | 填写内容 |
| --- | --- |
| 项目名称 | `prax-portal` |
| 项目目录 | `/www/wwwroot/prax` |
| 启动文件 | `server/index.js` |
| Node 版本 | 选 **v24 LTS**（≥22.13） |
| 运行方式 | `PM2` |
| 端口 | `3000` |
| 环境变量 | `NODE_ENV=production`、`HOST=0.0.0.0`、`PORT=3000` |

点确定。启动后状态应显示「运行中」。

### 方式 B：命令行 PM2（本项目已附带配置）

```bash
cd /www/wwwroot/prax
mkdir -p logs
pm2 start ecosystem.config.js
pm2 save
pm2 startup      # 按提示再执行一次它输出的那条命令，实现开机自启
```

常用命令：

```bash
pm2 logs prax-portal      # 看实时日志
pm2 reload prax-portal    # 改完代码平滑重启
pm2 status                # 查看状态
```

> **注意**：本项目用内置 SQLite（单文件数据库），`ecosystem.config.js`
> 已固定为**单实例（fork）模式**。不要改成 cluster 多实例——
> 多进程同时写同一个库文件会互相抢锁。

### 首次启动会自动初始化

服务启动时若发现数据库为空，会**自动灌入演示数据**（含 4 个账号、
6 个项目、3 个自建页面等），无需手动执行 `npm run seed`。

启动成功后先本地验证：

```bash
curl -s http://127.0.0.1:3000/healthz
# 期望输出：{"ok":true,"status":"healthy",...}
```

## 五、绑定域名并开启 HTTPS

### 1. 建反向代理站点

宝塔 → **网站** → **添加站点**
- 域名：`prax.yourdomain.com`（换成你的）
- 根目录：随便建一个（如 `/www/wwwroot/prax-proxy`），**不用于放代码**
- PHP 版本：**纯静态**

建好后点该站点 → **反向代理** → **添加反向代理**

| 字段 | 填写内容 |
| --- | --- |
| 代理名称 | `prax` |
| 目标 URL | `http://127.0.0.1:3000` |
| 发送域名 | `$host` |

### 2. 申请 SSL 证书

该站点 → **SSL** → **Let's Encrypt** → 勾选域名 → 申请。
成功后打开 **强制 HTTPS**。

> 本站已内置 `X-Forwarded-For` 支持（`app.set('trust proxy', true)`），
> 走反向代理后操作日志里记录的仍是访客真实 IP，不会被记成 `127.0.0.1`。

## 六、部署后必做

1. **改管理员密码**：登录 `/admin`（默认 `admin` / `admin123`）→
   内容管理 → 成员与权限 → 改掉 admin 的密码
2. **改站点信息**：系统 → 站点设置 → 站点名称、联系邮箱、品牌配色
3. **检查上传目录可写**：`chmod -R 755 /www/wwwroot/prax/public/uploads`
4. **测试页面编辑器**：内容管理 → 自建页面 → 新建 → 切换 Markdown / HTML，
   确认右侧预览正常

## 七、数据备份（重要）

数据只有两个位置，备份它们即可：

| 内容 | 路径 |
| --- | --- |
| 数据库 | `/www/wwwroot/prax/data/` |
| 上传的图片 | `/www/wwwroot/prax/public/uploads/` |

> SQLite 开启 WAL 模式，`data/` 下会有 `prax.sqlite`、`-wal`、`-shm` 三个文件，
> **务必整个目录一起备份**，只拷主库文件可能丢最近的数据。

### 用宝塔计划任务自动备份

宝塔 → **计划任务** → 添加任务：
- 任务类型：**Shell 脚本**
- 任务名称：`prax 数据备份`
- 执行周期：每天 03:00
- 脚本内容：

```bash
cd /www/wwwroot/prax
# 停写 3 秒让 WAL 落盘，再整目录打包，避免备份到半写状态
sqlite3 data/prax.sqlite "PRAGMA wal_checkpoint(TRUNCATE);" 2>/dev/null
tar -czf /www/backup/prax-$(date +%Y%m%d).tar.gz data public/uploads
# 只保留最近 14 天
find /www/backup -name 'prax-*.tar.gz' -mtime +14 -delete
```

> 如果服务器没装 `sqlite3` 命令，去掉那一行即可；`tar` 仍能备份到完整文件，
> 只是极端情况下可能包含未落盘的数据。

## 九、常见问题

### 启动失败：`No such built-in module: node:sqlite`

Node 版本过低。升级到 ≥ 22.13.0（推荐 24 LTS），
或临时用 `node --experimental-sqlite server/index.js` 启动（仅限 22.5+）。

### 启动失败：`EADDRINUSE: address already in use :::3000`

端口被占用。先查是谁：

```bash
netstat -tlnp | grep 3000
```

要么停掉占用进程，要么在本项目的环境变量里把 `PORT` 改成别的
（同时记得同步修改反向代理的目标 URL）。

### 页面能打开但样式全丢 / 图片 404

多半是反代没配对。检查反向代理的**目标 URL 是 `http://127.0.0.1:3000`**，
且站点根目录**不要**指向项目目录（PHP 站点会尝试自己处理静态文件）。
本项目全部静态资源都由 Node 服务自身提供。

### 上传图片失败

目录权限问题：

```bash
chown -R www:www /www/wwwroot/prax
chmod -R 755 /www/wwwroot/prax/public/uploads
```

### 后台上传大图报错

默认单文件上限 12 MB。要调整请改 `server/routes/admin.js` 里的
`limits: { fileSize: 12 * 1024 * 1024 }`。
同时宝塔的 Nginx 也有上传上限：站点 → 配置文件 → 调大 `client_max_body_size`。

### 想换 SQLite 数据库位置或上传目录

用环境变量外置（容器/宝塔都适用）：

```
PRAX_DATA_DIR=/www/wwwroot/prax-data
PRAX_DB_FILE=/www/wwwroot/prax-data/prax.sqlite
PRAX_UPLOAD_DIR=/www/wwwroot/prax-data/uploads
```

好处是把「代码」与「数据」分开，更新代码时完全不用碰数据目录。

## 十、无宝塔时的等价做法（参考）

如果你更习惯命令行，或宝塔装不上，等价流程是：

```bash
# 1. 装 Node 24（用 nvm 或 NodeSource）
curl -fsSL https://deb.nodesource.com/setup_24.x | bash - && apt install -y nodejs

# 2. 放代码 + 装依赖
cd /www/wwwroot && git clone <仓库> prax && cd prax
npm install --omit=dev

# 3. PM2 常驻
npm i -g pm2
pm2 start ecosystem.config.js && pm2 save && pm2 startup

# 4. Nginx 反代（把下面内容放进 server 块）
```

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```
